What This Automation Does

The script logs into Symplr Recruiting, opens the UAFCompare1 report, selects a requested date range, runs the report, and downloads the official Current Layout CSV from the export panel.

The correct file is the one named like Current_Layout-CSV_YYYYMMDD_HHMMSS.csv. The older files with _DOM_ in the name were experimental page-scrape files and should not be used as the final result.

The latest successful different-date test used 05/11/2026 and generated /Users/harsha/Downloads/Symplr/Current_Layout-CSV_20260517_174604.csv.

Horizontal Process Flow

These are the exact automation steps used to produce the CSV.

1 Login Opens Symplr and signs in with the configured automation account.
2 Open Report Navigates to Reports and selects UAFCompare1.
3 Set Dates Fills both date fields with the selected start and end date.
4 Run Report Clicks View Report and waits for the rendered results.
5 Export CSV Chooses CSV for Current Layout and downloads the file.

Why This Confirms The Right Result

The script now scopes the export controls to the Current Layout row, clicks the nearby Download option, then validates the downloaded CSV columns before marking the run successful.

How The Output Is Checked

The automation does not accept a file just because something downloaded. It performs these checks first.

Repository And Code Explanation

This repository is a small Python automation project. Its main purpose is to download the Symplr UAFCompare1 report as an official Current Layout CSV without manual browser work.

Important Files

Important Snippets

The script validates CSV columns using the real CSV parser instead of manually splitting text. This avoids false failures when the first header has a BOM or quotes.

with open(filepath, 'r', encoding='utf-8-sig', newline='') as f:
    reader = csv.reader(f)
    cols = next(reader)
    cols = [c.strip() for c in cols]

The script uses Playwright's download listener so it only continues after the browser actually creates a CSV download.

with page.expect_download(timeout=LONG_TIMEOUT) as dl_info:
    click_dropdown_option_near(page, "Download", export_dropdown_btn)

download = dl_info.value
download.save_as(str(dest))

The script scopes the export action to the Current Layout row. This prevents selecting the wrong report export option.

current_layout = page.locator(
    "div[data-name='selected-option'][data-id='Current Layout']"
).first
return current_layout.locator(
    "xpath=ancestor::li[@data-name='adaptable-object-list-item'][1]"
)

Date Logic

The report date follows a fixed two-week cadence from the known anchor date. If a scheduled report date falls on a weekend or holiday, that one report moves to the next business day. The next cycle still stays on the original every-two-weeks schedule.

Scheduled Cycle Date Reason Automation Uses
05/11/2026 Normal biweekly date 05/11/2026
05/25/2026 Memorial Day holiday 05/26/2026
06/08/2026 Next normal biweekly date after the 05/25 cycle 06/08/2026 
def next_biweekly_date(anchor=BI_WEEKLY_ANCHOR, today=None):
    today = today or datetime.date.today()
    scheduled = anchor

    while True:
        report_date = next_business_day(scheduled)
        if report_date >= today:
            return report_date
        scheduled += datetime.timedelta(days=BI_WEEKLY_DAYS)
The most important code fix was changing validation from manual comma splitting to csv.reader with utf-8-sig. That confirmed the file was correct instead of failing because of the hidden BOM at the start of Applicant Name.

Credential Setup

The script should not contain usernames or passwords. It now reads credentials only from environment variables.

export HIRE_USER="your-username"
export HIRE_PASS="your-password"

For a one-time manual run, set the variables in the same terminal before running the script.

cd /Users/harsha/Downloads/myapp
export HIRE_USER="your-username"
export HIRE_PASS="your-password"
.venv/bin/python scripts/download_hire_report.py --out /Users/harsha/Downloads/Symplr

For repeated local runs on macOS, store them in a private shell environment file and load it before running.

nano ~/.hire_report_env
export HIRE_USER="your-username"
export HIRE_PASS="your-password"
export DOWNLOAD_DIR="/Users/harsha/Downloads/Symplr"
chmod 600 ~/.hire_report_env
source ~/.hire_report_env
.venv/bin/python scripts/download_hire_report.py
Keep ~/.hire_report_env private and do not commit it to Git. The script now exits with Set HIRE_USER and HIRE_PASS environment variables if credentials are missing.

Windows VM / Task Scheduler Credentials

For the Windows VM plan, run_hire_report.bat includes the Symplr automation account so Task Scheduler can run without a manual terminal session.

set "HIRE_USER=sa-powerapps"
set "HIRE_PASS=Digital1500"

Task Scheduler should run this file:

C:\hire-report-automation\run_hire_report.bat
Because the password is stored in the Windows batch file for scheduled runs, keep the VM and project folder access restricted. If the password changes, update run_hire_report.bat.
